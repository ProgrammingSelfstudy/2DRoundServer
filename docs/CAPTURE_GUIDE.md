# 抓原服务器的包

目的：把原安装包在原服务器上的真实通信记下来，解开 `docs/OPEN_QUESTIONS.md` 里那些“客户端里没有数据、只能猜”的规则。

## 原则：只被动记录，不用脚本登录原服务器

用你手机上的**原版客户端**正常玩，同时用抓包 App 旁路记录。
**不要**用我们的机器人（`cmd/bot`）或任何自制客户端去登录原服务器：它的请求和真实客户端有细微差别，原服务器可能识别为异常，账号有被封的风险。
账号密码我不会写进仓库、文档和日志里，也不会拿去登录；你自己在手机上输入就好。顺带建议：账号密码已经在对话里出现过一次，抓完包后改一下密码更稳妥。

## 工具

- 手机：Android 上装 **PCAPdroid**（不需要 root，用 VPN 接口抓包）。
  设置里选：只抓目标 App（原版游戏），格式 **PCAP / pcapng** 都行，**不要**开 TLS 解密（游戏的 TCP 通信是明文，HTTP 部分也不需要）。
- 电脑：把手机导出的文件拷过来，用本仓库的解码工具：

```sh
go run ./cmd/pcapdecode -in session.pcapng -out testdata/captures/original-2026-10-20/capture.jsonl
```

它只读文件，不会连接任何东西。输出每一帧的时间、方向（c2s 客户端发的、s2c 服务器发的）、指令编号、解码后的内容和原始十六进制；终端末尾会列出每个指令出现的次数。
如果提示 “no game frames found”，说明抓到的数据里没有游戏的 TCP 连接，或者握手前的包丢了（要从“点开始游戏”之前就开始抓）。

## 抓什么，怎么操作

**每一段单独抓一个文件**，文件名写清楚，这样我知道哪个文件解决哪个问题。每段开始前先开抓包，做完就停。

| 文件 | 操作 | 解决什么 |
|------|------|----------|
| `01-newrole` | 用新号（或新建角色）：开抓包 → 启动游戏 → 选服 → 创建角色 → 进主城 → 打开“英雄”界面 → 停 | 起始英雄、英雄容量、11000/11025/11026 的真实数值、23200 里 `kv_list` 的含义、10302/10301 的初始数值 |
| `02-summon` | 基础召唤：免费单抽 → 用召唤券单抽 → 十连 → 高级召唤（有钻石的话）。每步之间等 2 秒 | 免费规则、`kv_list`、`flag`、保底、重复英雄、抽卡奖励 |
| `03-hero` | 同一个英雄：升 1 级、再升 1 级、突破（能的话）。每步前后都点开英雄详情 | 属性成长公式、战力公式、升级和突破的消耗与推送 |
| `04-campaign` | 战役：点挑战 → 布阵 → 出战，**多打几关**，包含一次胜利结算；再领挂机收益、快速作战一次 | 战斗真实的数据下发（20027、20002、20004、20006）、结算 13016、挂机和快速作战 |
| `05-gift` | 背包里开几种礼包：普通礼包、随机礼包、自选礼包 | 开礼包的真实规则（10515） |
| `06-shop` | 随机商店（杂货店）：打开、刷新、买一件；道具商店买一件 | 随机商店的商品池和价格、限购计数 |
| `07-misc` | 任务界面领一个任务；成就界面领一个；排行榜翻一页；升星（如果有材料） | 任务/成就的真实状态值、排行榜字段 |

最关键的是 **04-campaign**：我们现在的战役是“即时结算、没有战斗数据”，如果原版的战斗数据能抓到，就能知道客户端到底需要什么才能播战斗。

## 抓完之后

1. 把文件放进 `testdata/captures/original-日期/`，把 pcapdecode 的输出和一份简短的 `NOTES.md`（做了什么、遇到什么）一起放进去。
2. 告诉我哪个文件对应哪个问题，我读 `capture.jsonl`，把“我们自己定的规则”换成原版的，并把抓包做成回放测试。
3. 在 `docs/OPEN_QUESTIONS.md` 里把对应条目的状态改成“已确认”。
