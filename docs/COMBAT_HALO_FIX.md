## 两条不同路径

已有完整可读 Lua，直接核对源码，不需要重新反编译或运行手机：

- 客户端 `readable-source/lua/0zWHhlnBORyiROK6lvI6VBn6vAbJRQqS/battle/battle_model.lua:4310–4358`：`getFormIdListByCamp` 用于布阵预览。逐条精确核对 `pos_info` 列出阵营的数量，其他阵营不影响匹配；当当前行的 `condition` 指向的 ID 也匹配时，删除**当前行**。旧 Go 注释/实现把此方向写反。
- 同文件 `:4364–4384`：预览图标按升序 ID 组成十进制两位一组的编码。
- 客户端 `.../battle/new_view/battle_scene_view.lua:718–770`：实际战斗画面读取服务器的 `halo_list.type`，按万位、百位、末两位拆成最多三个 ID，直接用于显示；不会重新调用布阵预览排除逻辑。
- 客户端表 `.../ePoCrKQkWA3vpiOwu2oNfOh02MOeNheW/combat_halo_data.lua:449–529`，以及未变的 `internal/game/data/combathalo.json`：ID 21 要求基础五阵营各 1 人，22 要求阵营 4 为 1 人，23 要求阵营 5 为 1 人且 condition=21。表中 ID 21 的重复 `[5,1]` 是同一个计数条件重复出现，不代表阵营 5 要两人。

因此，把 Go 简单改成客户端预览方向也不够：五阵营各一人预览会留下 `[21,22]`，编码 2122；原服实际战斗帧是 `[21,22,23]`，编码 **212223**。将预览规则用于服务器战斗帧，是这次差异的根因。
