# 抓包计划（第二阶段，2026-10-28）

后端第一阶段做完以后，每个模块的规则几乎都是“照客户端代码和文字实现、没有和原服核对”。这份计划把需要核对的东西按**一个账号一次能点完**的顺序排好，配合 `CAPTURE_GUIDE.md`（工具、只被动抓、不用脚本登录原服）。每段抓一个文件，文件名写清楚；回来后 `go run ./cmd/pcapdecode -in x.pcapng` 解码，我按“解决什么”那一列核对并把 `OPEN_QUESTIONS.md` 里的“我们定的”改成“已确认”或改规则。

账号分三种，越往下越难得到：**A** 新号（几分钟）、**B** 一个正常养了一段时间的号（有 105+ 级、英雄、公会）、**C** 要等到特定日子或活动开着。
