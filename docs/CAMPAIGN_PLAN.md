# 主线战役：范围与计划

目标：让玩家能在主线里“过关、拿奖励、解锁下一关”，让任务、商店货币、养成材料有稳定来源。
**不做真实战斗**：客户端的战斗是靠服务器逐回合下发数据（20027 / 20002 / 20004 / 20006，共 270 多个字段）再播放动画。
伤害公式客户端里没有，硬做很可能和原版差得很远。所以先做“即时结算”：点挑战，服务器直接判定结果并弹出结算界面，不播战斗动画。

## 已有的东西

- 640 个主线关卡的顺序链（16 章，`drama_dungeons.json`）。
- 13000 推送：进度状态，主城建筑靠它生成。
- 客户端关卡表里还有：首通奖励（`show_items`）、每次挂机收益（`hook_items`）、敌方战力（`power`）、等级限制（`lev_limit`）。
- 常量：每关最多扫荡 5 次、挂机上限 12 小时（43200 秒）、扫荡券是道具 10003、快速战斗道具 10004。

## 阶段一：能过关（先做这一步）

| 13000 | 进度状态 | 已有，补上各章节的状态列表 |

要点：
- **胜负规则（需要你定）**：我们的战力公式不是原版的，客户端关卡表里的敌方战力是原版尺度（最后一关 53 万多，我们起始英雄战力只有一百多），两者没法比较。
  建议阶段一**一律判胜**，难度留给以后的真实战斗。你如果想要门槛，可以改成“出战英雄数量/等级达到某个值才能过”，但这个规则完全是我们自己编的。
- **首通奖励**：用关卡表的 `show_items`；重复挑战的奖励用 `per_hook_items`（关卡表第 15 列），这是我的理解，待抓包确认。
- 经验：英雄经验和角色经验的给法没有数据，阶段一只发物品奖励，角色经验不动。
- 任务：“快速作战”等每日任务的计数在阶段二接上。

## 不做的

- 战斗过程、技能、伤害（20027 / 20002 / 20004 / 20006）。
- 布阵（编队）。要先确认客户端点挑战前是否强制要求保存阵容。
- 回放、战报。
- 副本以外的战斗玩法：竞技场、公会 Boss、爬塔、无尽试炼。

## 风险（上真机才能知道）

1. 客户端点“挑战”后，如果服务器不推送战斗数据而直接发 13016，界面会不会卡在加载？
2. 点挑战前有没有强制布阵检查？
3. 13016 结算界面在没有战斗场景时能不能正常显示？

这三条决定了即时结算能不能行。如果不行，下一步就要做最小的战斗数据下发，规模会大很多。
**建议做完阶段一就上真机验证**，再决定后面的方向。

## 需要你决定的

1. 胜负规则：一律判胜（推荐），还是加一个自己定的门槛？
2. 是否同意阶段一先不发角色经验和英雄经验？


## 真机结果（2026-10-19，三星 SM-A165F）

风险 1 的答案是：不会“卡在加载”，而是**根本点不到挑战**。

- 战役界面是空森林，没有战斗人物，也没有“挑战BOSS”按钮。
- 客户端里这个按钮默认隐藏（`battle_drama_top_view.lua`：`btn_layout_status = false`），只在挂机战斗场景创建后显示（`battle_hook_model.lua: createBattleScence` → `updateBtnLayerStatus(true)`）。挂机场景要靠 20027（开场数据）等战斗推送才会建。
- 所以“即时结算、不推战斗数据”的方案行不通，必须先做**最小的挂机战斗数据下发**：登录进战役界面时推一场固定的挂机战斗，让场景建起来、按钮出现。
- 已确认并修正：13000 的 `status` 必须是 2（可挑战）且 `cool_time` 为 0，旧值 1 在客户端任何分支下都不显示按钮。
- 规模：20027 约 50 个字段、20002 约 98、20004 约 92、20006 约 32（含嵌套）。先做 20027 加一个固定的我方必胜回合，看场景和按钮能否出来，再扩展。

### 2026-10-19 技能与暴击

- 战斗脚本（`internal/game/fight.go`）改用客户端的技能表（`tools/extract_skills.py` → `internal/game/data/skills.json`，2052 个技能）：普通攻击与主动技能（`fire_cd` 首次回合、`cd` 冷却，抓包里第 1 回合全是主动技能、第 2 回合普攻，吻合）、目标规则（前方 / 随机 N 个 / 攻击最高 N 个 / 生命最低 / 全体）、伤害百分比、治疗（友军加血，正数 `hp_changed`）。技能号、效果号照抓包的规律发，客户端据此显示技能名横幅、暗屏和特效。
- 暴击：每个英雄的暴击率 = 自身 `crit_rate`（千分比）+ 基础 10%（`baseCritRate`，我们的规则，起始英雄为 0 的话永远看不到），倍率取英雄的 `crit_ratio`（1500 = x1.5）；`is_crit=1` 由客户端自己显示。抓包那一场没有暴击，暴击的真实公式未知。
- 没做：buff / 状态（眩晕、流血、护盾，需要 `buff_list`）、吸血和复活类技能、被动技能、怪物按关卡配置。

### 2026-10-19 buff 与状态效果

- `tools/extract_skills.py` 现在也读战斗 buff 表（`Config.SkillData.data_get_buff`，2097 条）：每个技能带 `buffs`（buff 号、几率、持续回合、种类、正负面）。几率取自技能描述（技能里写“出血”“晕眩”，buff 表里叫“灼烧”“眩晕”，所以按“N%概率”取）；技能 buff_des 里没有、但描述里写了的（攻击下降 20%、护盾）按描述去 buff 表里找。与抓包逐项对上：眩晕 28201 / 70%，灼烧 21001 / 50%，流血 21301 / 60%，攻击下降 23203，格挡盾 12501。
- 战斗脚本（`internal/game/fight.go`，引擎 `fightSim`）处理四类：**眩晕**（跳过行动）、**持续伤害**（灼烧/流血，每回合初扣 施法者攻击 × 15%，可叠加，各有各的 `id`）、**护盾**（挡一次伤害，随后移除）、**攻击下降**（攻击 -20%）；其余状态（禁疗、破甲……）只显示图标，不改数值。
- 下发格式：施放时在效果的 `buff_list` 里 `action_type 1`（加，带 `id`、`remain_round`、`end_round`，护盾 `end_round 100`），下一回合 20002 开头一条 play 用 `action_type 3` 更新剩余回合（抓包如此）。**`action_type 2` 表示移除是我们的猜测**（抓包只有两回合，没有到期的例子），持续伤害的伤害数字挂在 20002 开头那条 play 里（也是猜的格式）。
- 真机：状态图标和“攻击下降”飘字能显示，战斗不卡。眩晕、持续伤害、护盾没有在画面里亲眼看到（几率触发，起始英雄只有一个会眩晕的技能）。
- 没做：纯增益技能（加攻击、加护盾给自己）、驱散、免疫、吸血与复活、叠层上限、buff 的真实数值公式。

### 2026-10-19 纯增益技能

- 之前脚本把“没有伤害也没有治疗”的主动技能（920 个里的 470 个）一律当成不可用。现在会放：给自身 / 友军加状态的技能、驱散、纯控制技能。一个技能只有它带的状态我们能播（或有驱散）才算可用；可播的纯技能 123 个。
- `tools/extract_skills.py`：buff 表按描述分类，新增 `atk_up`（攻击提升）、`dmg_up`（伤害提升）、`crit_up`、`crit_dmg_up`、`dmg_reduce`（免伤）、`speed_up`、`regen`（持续回复，基数取施法者攻击或生命上限）；友军/自身目标（自身、己方全体、攻击最高 N 个、随机 N 个、随机单体、生命最低 N 个）；`purge` / `purge_chance`（驱散个数与几率）；治疗和伤害的正则放宽（“回复随机 3 个己方单位等同自身攻击力…”）。抓包里已知的技能结果与之前逐项一致。
- `internal/game/fight.go`：状态的数值——攻击提升/下降改变攻击，伤害提升/免伤改变出手和受到的伤害（免伤最多 90%），暴击率提升按 1% = 10 千分比、暴击伤害提升加到倍率，速度提升改变出手顺序，持续回复每回合初加血（不超过上限），驱散先移除最新的负面状态（不能驱散的保留）。纯增益技能每个目标一条 `effect_play`（`hp_changed` 0，`buff_list` 为 `action_type 1`）；目标已经带着同一增益（不叠加的）时改用普通攻击，不重复施放。
- 真机：怪物“大舞刀”（给随机己方单体加 25% 攻击和 20% 暴击伤害）施放后，右边的怪物头上出现“攻击提升”“暴伤提升”和两个状态图标，第 6 回合冷却到了再次施放；战斗 7 回合正常结算。英雄的“天空护”（自身免伤）、治疗加驱散（“生命释放”）、持续回复、驱散这轮在画面里没有亲眼看到，只有测试覆盖。
- 我们的规则（原服务器未知）：增益的数值取 buff 描述里的百分比；暴击率“%”折成千分比；免伤上限 90%；驱散顺序；`speed_up` 只处理“N%”形式，固定数值的速度提升只显示；`side 7` 的技能（7 个）仍跳过。
- 没做：防御/抵抗/闪避/治疗提升等没有数值模型的状态（只显示图标）、叠层上限、被动技能、吸血与复活。
- **以后抽离技能系统时整体搬走这几处**：`skillRule` / `buffRule` / `activeBuff`、`skills.json` 和 `tools/extract_skills.py`、`pickSkill` / `usable` / `pickTargets` / `targetsOf` / `worth` / `purge`、`fightSim` 的 `act` / `addBuff` / `startOfRound`（都在 `internal/game/fight.go`）；战斗服务本身（`FightService` 的开场、回合推进、结算）留在原处。

### 2026-10-19 跳过战斗与失败结算

- **跳过**：战斗界面右边的“跳过”按钮发 `20062`（客户端对战役一律显示该按钮）。服务端：有正在进行的战斗就回 `20062 {code 1}` 并立刻按脚本结果结算（胜利 `13016`、`13001`、`10302`、`10500`；失败只有 `13016`），战斗状态清掉，之后客户端迟到的 `20005`/`20019` 被忽略；没有战斗时回 `20062 {code 0, msg}`（客户端弹提示）。原服务器跳过时发什么没抓到，这是我们的做法。真机：第 6/15 回合点“跳过”，直接出“挑战成功”结算窗口，进度和奖励正确。
- **失败**：战斗脚本现在带胜负——我方全灭，或超过 15 回合（客户端显示的回合上限，`maxFightRounds`）怪物还活着算输。失败发 `13016 {result: 2, item_rewards: []}`，不发 `13001`、不给奖励、不推进关卡，同一关可以再挑战。客户端对 `result != 1` 一律走通用失败窗口（`BattleController.openFinishView` → `openFailFinishView`）；**`result = 2` 是猜的**（没抓到过失败），真机上用“英雄血量 1”的临时副本验证：弹出“战斗失败”窗口（带英雄召唤、英雄培养、更换装备、提升神技），进度和贝里不变。
- 正常流程里英雄几乎打不死（怪物伤害很低），失败路径目前只会在特殊情况触发（全灭、被一直眩晕、回合用完）；怎么让难度随关卡上升要等“每关真实怪物”。
