# 抓包详细步骤（A~D 单号 10 项 + E 公会社交 + F 日常活动 + G 付费窗口）

`CAPTURE_CHECKLIST.md` 是总清单（一项一行）；这份把**账号 B 现在就能做、价值最大**的几项展开成可以照着点的步骤。
工具和原则见 `CAPTURE_GUIDE.md`：只被动抓、不用脚本登录原服、不开 TLS 解密、**从点“开始游戏”之前就开抓**。

## 通用流程（每一项都一样）

1. 先**不开抓包**，在游戏里把准备工作做完（选好英雄、凑好材料、打开到目标界面的上一级）。
2. 退回登录界面或杀掉游戏，开 PCAPdroid（只抓原版游戏），**开始抓** → 启动游戏 → 登录进主城。登录包必须在文件里，否则解码会报 “no game frames found”。
3. 进主城后**等 3 秒**，再做步骤。每个动作之间**等 2 秒**，这样回包和推送能按顺序分开。
4. 做完最后一步后**再等 3 秒**（让尾部推送到齐）→ 停止抓包 → 导出文件，用下面的“文件名”命名。
5. 写一份 `NOTES.md` 条目：做了哪几步、**每步前后的数值**（英雄等级/星级/战力、材料数量、钻石金币）、遇到的提示文字原文。数值是对公式的唯一依据，抓包里没有“界面上看到的数”。
6. 电脑上解码：`go run ./cmd/pcapdecode -in x.pcapng -out testdata/captures/original-日期/<文件名>.jsonl`，终端末尾看每个指令的次数，对一下“应该看到”那一栏。
7. 对不上就别删文件，在 NOTES 里写“这步没触发”，我会按剩下的包判断。

**记数值的小技巧**：每步前后各截一张图（英雄详情、背包材料、钻石金币），图名带步骤号，如 `a01-s3-before.png`。

## a01-hero-starup　英雄升星（11005）

**剩余重点**：原服已有5→6、6→7和7→8成功；继续补材料不足、锁定材料禁选/提示、2.8魂石和2.9融合升星。已有材料列表和成功推送记录不需要重复消耗资源。

**准备**
- 选一个 **4 星**英雄 X，不要锁定，不要在共鸣位。记下它的 bid、等级、战力。
- 材料英雄：同一 bid 的低一星英雄（或升星界面里写明的指定星级英雄）凑满材料位；**另外多留一份**完整材料，用于第 4 步以外的重试。
- 若背包有魂石类材料，单独记下数量；有 20 星以上的英雄，另做第 6 步。

**步骤**（每步前截图）
1. 进主城，打开英雄列表，点英雄 X → 详情。等 2 秒。
2. 点“升星”，**界面停在材料选择，先不点确认**，截图（记下材料位几个、各自要求）。
3. 把材料放满 → 点确认。等 3 秒，看英雄新星级、战力、被消耗的英雄是否消失。
4. **材料不足**：对另一个英雄 Y（4 星，材料故意少放一个）点确认。如果按钮灰不可点，记“按钮灰”并截图提示文字，不算失败。
5. **锁定的材料**：（需要 a03 做完）放一个被锁定的英雄当材料，记提示文字。
6. 有魂石 → 用魂石材料升一次；有 20 星以上英雄 → 做一次融合升星。没有就写“无”，别硬凑。
7. 回主城，等 3 秒，停。

**应该看到的包**
- 11005 请求 + 回包（`msg`、`result`；请求里材料放在 `expend1` 还是 `expend2`）。
- 11002（X的新属性）、11006（材料删除）；按实际成本/返还检查10302、10510/10512和10306。**记录实际顺序，不假定这些包每次全部出现**；已抓成功样本均11006先于11005确认，msg为空。
- 材料不足时记录11005的实际回包；如果界面拒绝提交，保留截图、按钮状态和提示，无包也可以作为有界面证据的结果。

**解决**：2.8、2.9、2.10、2.11；回包 `msg` 原文。

**2026-11-03结果**：鳄鱼id1005已补5→6、6→7。6→7材料含100级萨博id13，原服返还培养资源和穿戴物，并将5名共鸣槽英雄从35更新到6级；突破卡返1850、花1000、净增850。本次无10306。剩余不足/锁定/魂石/融合分支尚未确认。见[详细解析](../testdata/captures/original-2026-11-03/HERO_STARUP_EXTRA_NOTES.md)。
